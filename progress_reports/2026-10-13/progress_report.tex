\pagehead{2. Earlier routing tests and the change in method}
\textit{Screening} was a preliminary accuracy check, not a learning method. Each pruned model was compared with its own unpruned model (p0) to see whether its accuracy loss stayed below 0.5, 1, 1.5 or 2 percentage points. For example, MobileNetV3-Small p10 scored 60.82\% against p0's 62.44\%: a loss of 1.62 points, so it passed the 2-point check but not the 1.5-point check. Its MAC count was 27.11\% lower. No pruned ResNet, EfficientNet or MobileNet-Large passed even the 2-point check. This left nine source models, or 27 precision configurations.

That shortlist was abandoned as a restriction on routing. A model can have lower overall accuracy yet correctly classify images that another model gets wrong. All 213 configurations therefore remain selectable. The original screening used historical test accuracy and is only descriptive; current policy selection uses validation data. The rejected pruning and quantization results remain recorded.

The earlier scalar routers predicted a single score derived from the cheapest correct candidate's position in a cost ordering. Methods included a gradient stump, depth-3 tree, logistic regression, depth-2 XGBoost and TinyCNN. Image-tree scores were combined using the mean or percentiles 10/25/50/70/80/90. The logistic target was a binary rank-related target, rather than a separate correctness estimate for every candidate.

\pagehead{3. Model complementarity and correctness-router training}
For each seed (42/45/48), the 5,000 classifier-validation images were divided into 3,000 router-training and 2,000 policy-calibration images. ``Validation-only'' refers to the source of this supervision: the router was trained, but no held-out test labels were used to fit its weights or choose its policy. The 10,000 test images were used for final evaluation. One limitation is that the same 5,000-image validation set had already informed classifier checkpoint selection.

The validation-selected reference, ResNet-101 p0 FP32, obtained 85.88\%. An oracle that knows the correct label and can choose per image obtained 99.28\% over all 213 candidates: only 36 of 5,000 images were wrong for every model. Restricting this oracle to the eight unpruned FP32 models gave 95.68\%. These are upper bounds, not measured learned-router performance. MobileNet-Large p0 FP16 corrected 250 reference errors but made 441 errors on images the reference got right; EfficientNet p0 FP16 corrected 246 and introduced 383. Their lower total accuracy therefore does not imply that their predictions are redundant.

The router uses a 16$\times$16 image thumbnail, a small depthwise CNN and 213 output logits. Each output learns whether its corresponding classifier is correct, using binary cross-entropy; several outputs can be correct on the same image. Training used 20 fixed epochs and Adam with learning rate 0.001. For batch $B$, the selected model is
\[
q_m(B)=|B|^{-1}\sum_{x\in B}\sigma(z_m(x)),\qquad
m^*(B)=\arg\max_{m\in\{1,\ldots,213\}}\left[q_m(B)-\lambda\frac{C_m(B)}{\max_j C_j(B)}\right].
\]
Here $q_m(B)$ is the mean predicted correctness of model $m$ over the batch, and $C_m(B)$ is its measured static cost. The penalty $\lambda$ is calibrated separately for latency and energy under allowances of 0.5/1/1.5/2\pp. The accuracy constraint applies to the resulting policy, not to every model individually. A lower-accuracy model can therefore be selected for a batch if the router predicts that it will perform well on those inputs.

Three router fits and six objective/seed calibration groups completed. Each seed was exported to six fixed-shape TensorRT engines, including the true final batch of 16. Maximum PyTorch/TensorRT output differences were $2.3842\times10^{-7}$ for seeds 42/45 and $1.7881\times10^{-7}$ for seed 48. The times below cover fitting, export and calibration, not classifier training. The reduction in fitting loss does not, on its own, establish test accuracy or runtime savings.

Per-model correctness supervision was already present in the earlier 10-candidate benchmark. The current experiment extends it to 213 architecture/precision/pruning choices with measured cache and inference costs. PERTINENCE \cite{pertinence} and Taylor et al. \cite{taylor} are closely related input-based model-selection studies. DynamicDet \cite{dynamicdet} motivates defining difficulty through the benefit of additional computation; CARN \cite{carn} and adaptive-inference policies \cite{adaptive} provide other relevant comparisons.

\pagehead{5. Discussion and remaining work}

In latency/42/b128/2\pp, the router selected R101 FP16 for 5,136 images and R34 FP16 for 4,864. The corresponding 1\pp settings selected R101/EfficientNet for 7,040/2,960 images (seed 45), and R101/R34 for 7,424/2,576 (seed 48). These examples used two loads and no evictions per repeat. All 213 models were available; the concentration on two models was the policy's outcome, not an imposed shortlist. However, 67 tests failed the accuracy allowance, and no latency setting both passed and improved on its comparator for all three seeds.

Timing includes RGB transfer, GPU normalization, the router, selection, engine loading/eviction, inference and synchronization. Decode/resize and batch pinning are excluded equally from both paths. The example routers spent about 1.30--1.34\,ms/batch on the GPU decision component. Training took seconds; five full passes and fresh static comparisons per configuration accounted for much of the testing time. NVML measures GPU energy, including idle/display load, not whole-PC energy. Sequential timing and temperature/load changes remain possible sources of variation, so alternating static/routed tests is a priority.

\textit{Jetson.} The study is paused with 75/213 engines built and accuracy-validated, 74/213 fully measured static targets, and 2,232/6,390 energy repetitions. EfficientNet and MobileNet-Large account for 60 targets/1,800 repeats; MobileNet-Small p40 INT8 has 12/30 repeats saved, ending at batch 16, repeat 1. Three architectures are staged; five still need transfer. The last saved target reached 54.375$^{\circ}$C. No new global Jetson routing has run. Detailed target results remain on the paused device; the local update uses its verified checkpoint counts. Engines must be built with Jetson TensorRT 8.6.2, not reused from the PC.

\textit{Next experiments.} The eight classifiers used the same 45,000 training and 5,000 validation images, with no unused reserved pool. More router supervision would require either explicitly exploratory predictions on classifier-training images, or slower classifier retraining/out-of-fold predictions. This choice is still pending. Seven additional correctness routers are prepared: depth-1/depth-3 trees, logistic heads, depth-2 XGBoost (32 trees per candidate), and TinyCNN inputs 8/16/32. The current smaller CNN remains a separate baseline. Eleven CPU tests passed in 15.699\,s; real-data GPU fitting, export and runtime evaluation are unfinished.

The proposed first comparison uses seed 42, batches 32/128, latency/energy objectives and 1/2\pp allowances, with one full-test repeat: 56 configurations, or 64 with a newly trained current-CNN baseline. Full confirmation would add multiple seeds and five repeats, giving 840 additional tests (960 including the existing 120). No parameters will be selected from the completed test results. Per-configuration numbers and source hashes remain in \code{numerical\_summary.json}; full repetitions are retained locally in \code{numerical\_results.json}. Automation is paused, and this revision did not restart any experiments.
