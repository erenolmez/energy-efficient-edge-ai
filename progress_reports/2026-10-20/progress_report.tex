\section*{1. From scalar routing to correctness routing}
We used classical feature-based predictors and lightweight convolutional neural networks (CNNs). We changed from a scalar cost-rank target to 213 correctness targets to exploit PERTINENCE's motivation: \textbf{models have complementary strengths}. A model with lower overall accuracy can outperform a stronger model on particular inputs.

\textbf{Training data.} Base classifiers received 45,000 image/class-label pairs. Each router used a 5,000-image development pool with separate fitting/calibration subsets: scalar training paired batch mosaics/features with mean cost-rank targets; correctness training paired images with 213 correct/wrong targets derived from saved classifier predictions. Frozen policies were evaluated on 10,000 test images; no true labels enter deployed routing.

\textbf{Scalar routing: training target and model selection.}
\begin{enumerate}[leftmargin=1.5em,itemsep=.15em,topsep=.2em]
\item Measure candidate costs at the chosen batch size. For latency, order models from fastest to slowest; for energy, order them from least to most GPU energy. This ordering uses \emph{cost}, not accuracy.
\item Use all candidates' saved predictions on each labelled fitting image to mark them correct or wrong.
\item Find the \emph{cheapest candidate that was correct on that image}. If its zero-based position is $r$, the training target is $s=r/(M-1)$, where $M=213$. If every candidate fails, use the reference model's position as fallback.
\item Average the per-image ranks to obtain the batch target; train the scalar CNN with mean squared error (MSE). No true labels enter inference.
\end{enumerate}
For five cost-ordered candidates A--E, if A/B fail and C/D succeed, C has rank 2 and target $2/(5-1)=.50$. This is \textbf{not 50\% confidence}: it encodes the cheapest successful position.

\textbf{Scalar calibration: choosing the score-to-model mapping.} Calibration is a rehearsal, not more weight training. With the predictor fixed, try 1,601 biases $b\in[-1,1]$ on labelled calibration images. Each bias changes the selected cost position to $\operatorname{clip}(\lfloor(z+b)M\rfloor,0,M-1)$ for score $z$. Count the chosen classifiers' correct answers using saved predictions; estimate their cost. A reference accuracy of 86\% with a 1-point allowance requires 85\%. Keep the cheapest passing mapping, otherwise the reference alone. With five candidates, $z=.46$ selects C for $b=0$, B for $b=-.10$. Freeze $b$ before testing; no test labels enter calibration.

\textbf{Correctness routing: targets, training and model selection.}
\begin{enumerate}[leftmargin=1.5em,itemsep=.1em,topsep=.15em]
\item \emph{Targets:} for each labelled fitting image $x$ and candidate $m$, set $y_m(x)=1$ if the saved prediction equals the true class, otherwise 0. Each image has 213 binary targets. A wrong/B correct/C correct gives $(0,1,1)$: unlike scalar rank, it preserves both successful alternatives.
\item \emph{Input and training:} the TinyCNN receives normalized RGB image content pooled to $16\times16$, not the true class or candidate predictions. Its 213 logits become probabilities $p_m(x)$ through sigmoid. Binary cross-entropy compares every output with its correct/wrong target; weights learn image patterns associated with candidate success.
\item \emph{Outputs:} $p_m(x)$ estimates the probability that candidate $m$ classifies image $x$ correctly, not its CIFAR-100 class. Outputs need not sum to one: several candidates can succeed. Average each candidate's probabilities over the batch to obtain $q_m$.
\item \emph{Selection:} let $C_m$ be measured latency or GPU energy at this batch size, and $C_{\max}$ the largest cost. Choose the candidate maximizing $q_m-\lambda C_m/C_{\max}$. For hypothetical $q=(.70,.90,.85)$, normalized costs $(.20,1,.40)$ and $\lambda=.10$, scores are $(.68,.80,.81)$: C wins and predicts classes for the whole batch.
\end{enumerate}
\textbf{Correctness calibration: choosing the cost-preference dial.} Keep CNN weights fixed and try penalties $\lambda$: smaller favours predicted success, larger favours cheaper models. For each setting, select models for calibration batches and count their \emph{actual correct answers} using saved classifier predictions and calibration labels, not CNN confidence. Keep the lowest estimated-cost setting meeting reference accuracy minus the allowance; otherwise use the reference. Calibrate latency/energy separately, then freeze the policy. Passing calibration does not guarantee a test accuracy pass.

\section*{2. Why the 1.5-point results change sharply}
\textbf{The smaller model at 1.5 points is the static comparator, not necessarily the router's choice.} The router selects a model per batch; validation independently selects the cheapest eligible \emph{fixed} benchmark. Allowances are percentage-point losses (pp). Relaxing one can admit a much faster benchmark even if routing does not change.

\textbf{Exact example: latency, seed 48, batch 128.} R101/R50/R34 mean ResNet-101/50/34; FP16/FP32 are 16/32-bit floating point; b64 means batch 64. Both 1 and 1.5 policies use R101 FP16 for 7,424 images and R34 FP16 for 2,576. R50 FP16 is the new \emph{benchmark}, not the router choice: its calibration loss 1.35 pp first qualifies at 1.5.

\textbf{Fixed-benchmark columns:} hold the 1-point reference at 1.52280 ms/image and 47.2306 mJ/image for all rows; these are renormalized savings, not new measurements. The 1/1.5-point values stay near 16\%, revealing the moving denominator. At 1.5, $100(0.865-1.277)/0.865=-47.66\%$: the same routing is slower than the newly eligible benchmark. At 2 points, routing becomes faster but accuracy 82.25\% fails the required $85.80-2=83.80\%$ ($*$).

\textbf{Why this repeats.} Across the original 120 rows, eight settings flip from positive savings at 1 point to negative at 1.5: both objectives, seed 48, batches 16/32/64/128. All eight replace R101 FP16 with R50 FP16 as benchmark. Three turn positive again at 2 points (latency b64/b128, energy b128); \emph{all three fail accuracy}. This is not a universal middle-budget anomaly: at b8 several budgets are negative throughout.

\textbf{A separate switching-cost effect.} For latency/seed42/b8, the benchmark does not change, but engine loads rise 217$\to$313 and evictions 215$\to$311 from 1 to 1.5 points; routed time rises 69.46$\to$99.81 s. Calibration omits these loading costs, so a relaxed allowance can select a worse switching pattern. Residual differences between identical policies remain unexplained measurement instability.

\section*{Why machine learning rather than scalar optimization?}
\textbf{Answer: ML supplies input-specific estimates; optimization chooses the action.} Average accuracies/costs support a fixed choice; learned estimates can adapt it to the image. Our scalar router was also ML. Better choices must repay preprocessing, router and cache overhead at the required accuracy. \href{https://arxiv.org/abs/1810.01270}{META-DES} (Cruz et al., 2015) improved accuracy on 30 small-sample problems, not GPU energy/latency in our system.

\section*{3. Can a model be replaced without retraining the whole router?}
\textbf{Current design versus proposal.} The current 213 outputs are tied to named candidates: replacing B leaves its output predicting old B. A proposed \emph{shared scorer} instead takes an image--model pair. For image $x$, an ML encoder computes visual features $h(x)$ once. Model profile $d_m$ contains validation class-wise accuracy, precision/pruning and measured costs. The same ML scorer receives the joined vector $[h(x),d_m]$ for each available model and predicts its success probability $p_m(x)$. A non-ML cost rule then selects the classifier.

\textbf{Training and changes.} Offline labelled image--model pairs give correct/wrong targets for binary cross-entropy; profiles use separate evidence. No test labels enter inference. Remove 50 models by omitting their profiles/calls; the current CNN can also mask 50 outputs. Add a model by collecting validation predictions, profiling costs and inserting its profile, then validating/recalibrating the policy. No new head is needed, but accuracy is not guaranteed: test entirely held-out candidates, and fine-tune/retrain if needed. This proposal still requires initial offline training and model profiling.

\textbf{Related work (untested extensions here).} \href{https://arxiv.org/abs/2001.10741}{Tornede et al.\ (2020)} describes instance--algorithm pair scoring; \href{https://arxiv.org/abs/1810.01270}{META-DES} learns competence. \href{https://arxiv.org/abs/1703.06114}{Deep Sets} (Zaheer et al., 2017) could summarize model profiles, with extra computation; changing lists does not require it.

\section*{4. Does the learned router beat uniform random selection?}
\textbf{Answer: yes on accuracy in all 24 settings at each batch size.} At batch 64, learned accuracy is 81.86--85.64\% versus 36.26\% for uniform random; at batch 128 it is 82.25--85.39\% versus 36.25\%. Learned median latency is lower in all 24 settings at each batch; GPU energy is lower in 24/24 at batch 64 and 21/24 at batch 128. Uniform draws from all 213 candidates, including severe pruning/quantization failures. Beating it does not establish an advantage over a good static model.

\textbf{Comparison with the previous table.} Match objective, seed, batch and allowance to the 13 October correctness matrix. All 48 fresh learned accuracies equal the corresponding previous values, and fresh selection counts reproduce the frozen policies. Timings are remeasured, not copied. Each batch study comprises 495 full-test sweeps, with five trials per setting. Historical coverage: 52 global scalar settings and 120 correctness settings; scalar CNN fitted/exported, not globally measured.

\textbf{Reading the table.} ML is learned routing; R is uniform random. Accuracy columns show ML / R percentages (five-trial means). In each cost cell the pair is latency saving \% / GPU-energy saving \%, not raw costs. $\delta$ is the allowed accuracy loss in percentage points (pp); $*$ marks learned mean accuracy failing its allowance against the 85.80\% R101 FP32 reference. Every uniform row fails. L/E in Obj./seed denotes the latency/energy calibration objective.

\textbf{Savings baseline.} The Benchmark identity is the original 13 October validation-selected eligible static model, measured afresh per case. Saving is $100(C_{\rm benchmark}-C_{\rm method})/C_{\rm benchmark}$ for repeat-median latency or energy. Positive means cheaper; negative means worse. Identity is the same for the paired batch-64/128 rows, but its measured cost differs by batch and case.

\textbf{Shared random trials and uncertainty.} Uniform controls are reused across objectives/allowances, not independent experiments per row. For seeds 42/45/48, accuracy mean $\pm$ sample standard deviation is respectively 36.36$\pm$2.64, 36.67$\pm$1.47, 35.76$\pm$2.12\% at batch 64, and 36.15$\pm$2.07, 37.28$\pm$4.22, 35.34$\pm$2.57\% at batch 128. Different row benchmarks explain why identical random measurements can have different savings.

{\small \textbf{Implementation details.} Scalar inputs: 13 statistics (RGB/grayscale/gradient mean/std, edge density, saturation proxy, brightness variation). Scalar TinyCNN: 16 sampled $8\times8$ tiles; $3\to16\to24\to32\to48$, depthwise/pointwise blocks, batch normalization/ReLU, global pooling, 48-to-1 linear layer. Correctness CNN: $3\to16\to24\to32$, strided depthwise/pointwise ReLU blocks, global pooling, 32-to-213 linear layer, no batch normalization; 20 epochs, Adam 0.001, minibatches 64; seeds 42/45/48.}

\textbf{Timing boundary and caution.} Both paths include fresh GPU preprocessing, load/eviction, inference and synchronization (cache capacity 2). Learned routing also runs its CNN; random dispatch lookup is timed, schedule generation is not. Observed GPU thermal/power limits and R101 FP32 sweep times 15.4--58 s prevent attributing every timing change to routing. All accuracy failures remain; test results never retuned policies.

\section*{5. Always using a fixed 80\%-pruned model}
\textbf{Answer: lower cost, but unacceptable accuracy loss.} These completed p80 controls reach 0.93--22.55\% accuracy, versus 85.80\% for unpruned R101 FP32. None meets a 0.5/1/1.5/2-pp allowance. Here p80 means the nominal 80\% pruning setting, not a guarantee of 80\% fewer operations; INT8 is 8-bit integer precision. Seven architectures, three precisions, four batches and five repeats plus references give 440 sweeps. ShuffleNet has no pruned variant.

\textbf{Comparison with 13 October.} Its correctness router reached 81.86--85.64\% across batches 64/128, far above p80. Against the same \emph{type} of fixed R101 FP32 reference, earlier routing latency/energy saving ranges were: b8 $-336.2$ to $+61.1$ / $-160.7$ to $+60.4$\%; b32 $+60.9$ to $+76.3$ / $+61.3$ to $+76.5$\%; b64 $+61.5$ to $+87.4$ / $+63.6$ to $+87.5$\%; b128 $+60.0$ to $+81.8$ / $+60.5$ to $+82.0$\%. These are separate ranges across policies, including accuracy failures, not one policy achieving every endpoint. P80 saves more cost in many rows, but sacrifices most classification accuracy.

\textbf{Savings baseline.} Table pairs are latency saving \% / GPU-energy saving \% versus fresh, same-batch R101 FP32, matching the earlier \emph{vs-FP32} definition, not the routing table's eligible-static benchmark. Accuracy is the repeat mean; costs are repeat medians. Separate sessions and observed GPU throttling limit direct cross-study timing claims.
